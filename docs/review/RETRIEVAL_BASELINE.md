## 怎么跑

```sh
.venv/bin/python scripts/eval_retrieval.py \
    --username dev --password p18-review-2026 \
    --cases tests/fixtures/retrieval_baseline.json
```

评分按**证据文本**（子串）而不是 chunk id：chunk id 每次重建都会变，事实不会。
所以换解析器、换语料、换切分参数之后，同一批问题仍然可比。

- Core@k：前 k 条里至少命中一个期望事实
- Complete@k：前 k 条里命中全部期望事实
- 不可答题（`facts` 为空）：只记录 Top1 分数，用于看阈值能不能切开

## 唯一有信息量的发现

**不可答题的 Top1 分数（0.32–0.506）与可答题（0.449–0.683）严重重叠。**

意思是：**靠相似度阈值切不出"能答/不能答"**。设 0.45 会误杀"晨间校准"（0.449），
设 0.5 会放过"单位是分钟还是小时"（0.506）。

这解释了 P18 为什么在 RAG 层做拒答（`insufficient_evidence`），而不是在检索层设阈值
——阈值只能过滤明显无关，不能判断"证据是否足够回答"。

## 已知限制

- 无相似度阈值，不可答题也会返回 5 条
- 去重按正文内容，不按文档；同文跨文档会合并
- PDF 无 OCR（Docling PDF 管线默认关闭）
- 没有 Reranker（BGE 实验因 Complete@3 退步被否）
