# 企业化改造：设计与实施计划

依据 2026-11-15 的并发实测（并发 5 → QPS 6.0；并发 20 → QPS 5.9、p50 3.6 秒）
与六项根因，按「先测量、再改架构、最后上部署」分四期。每期都有可复测的验收指标。

## 现状基线（修复前）

| 场景 | 并发 | QPS | p50 |
|---|---|---|---|
| 列表 | 5 / 20 | 6.0 / 5.9 | 820 ms / 3 368 ms |
| 检索 | 5 / 20 | 5.6 / 5.5 | 892 ms / 3 579 ms |

吞吐与并发无关（约 6 QPS），说明瓶颈是服务端串行，不是网络或客户端。

## 六项根因

1. 单进程单 worker（`uvicorn workers=1`）
2. 全局 `LOCK` 串行化读路径
3. SQLite 单写 + 每文档一次索引状态查询
4. Qdrant 本地模式（单进程 + 目录锁）
5. 本地 Embedding 串行（`LocalQwen` 内部锁，一次一条）
6. 索引单线程（`ThreadPoolExecutor(max_workers=1)`）

## 第一期：把读路径的串行去掉（不换存储）

| 动作 | 预期 | 验收 |
|---|---|---|
| 索引状态批量读取：一次查询取全部 `index_runs`，列表不再逐份查 | 列表 120 ms → <40 ms | 列表 QPS ≥ 20，p50 < 200 ms |
| 列表不再持有全局锁做序列化构造，只在取数据时持锁 | 读并发不再互相排队 | 并发 20 时 p50 < 500 ms |
| 搜索查询向量缓存（同问题 60 秒内复用） | 重复提问不再重复编码 | 同问题并发 20，p50 < 300 ms |

不改存储、不改协议，风险最低，先拿收益。


## 第一期结果（2026-11-15 实施后复测）

同一台机器、同一批 123 份文档、同一脚本 `scripts/load_probe.py`：

| 场景 | 修复前 | 修复后 | 变化 |
|---|---|---|---|
| 列表 5 并发 | 6.0 QPS / p50 820 ms | **55.7 QPS / p50 86 ms** | QPS ×9.3，延迟 ÷9.5 |
| 列表 20 并发 | 5.9 QPS / p50 3 368 ms | **55.6 QPS / p50 350 ms** | QPS ×9.4，延迟 ÷9.6 |
| 检索 5 并发 | 5.6 QPS / p50 892 ms | 6.1 QPS / p50 813 ms | 基本持平 |
| 检索 20 并发 | 5.5 QPS / p50 3 579 ms | 6.1 QPS / p50 3 250 ms | 基本持平 |

做了什么：

1. 索引状态批量读取 —— 列表不再逐份查 `index_runs`（一次查询取全表，
   严格校验仍留在详情接口）
2. 列表先切片再构造记录 —— 一页 10 条不再为全库付索引查询的成本
3. 查询向量缓存（同问题 300 秒内复用）—— 已实现，**但检索吞吐没有变化**

### 检索为什么没变

缓存命中后省掉的是 Qwen 编码，但检索的大头不在这里：每次检索仍然要
`candidates()` 遍历全部文档、重建快照（`snapshot` + `chunks` 读库），
并且这一段在全局锁内。**瓶颈是候选集重建，不是编码。**

这条要放到第二期：把「文档 → 有效快照」做成内存缓存并在文档变更时失效，
才能让检索真正并发起来。

## 第二期：状态外置（为多 worker 铺路）

| 动作 | 原因 |
|---|---|
| 会话/草稿/票据从进程内存搬到 SQLite（带 TTL） | 现在 `sessions/drafts/tickets` 在进程内，多 worker 会互相看不到 |
| `MANAGED_RAG` 按会话改为无状态构造 | 同上 |
| 索引状态查询改为单条 SQL JOIN | 去掉逐份 snapshot |

验收：两个 uvicorn worker 同时服务，登录后任意 worker 都能续上会话。

## 第三期：把重活移出请求进程

| 动作 | 原因 |
|---|---|
| 解析/切分/索引走独立 worker 进程 + 任务表 | 现在靠线程池 + 子进程，重启即丢 |
| Embedding 独立服务（可换 GPU 或批量） | CPU 串行是检索吞吐的硬顶 |
| 去掉 180 秒单文档上限，改按任务类型配置 | 大 PDF 与 Docling 冲突 |

验收：并发上传 50 份不互相阻塞；服务重启后任务可续。

## 第四期：换存储与部署

| 动作 | 原因 |
|---|---|
| SQLite → PostgreSQL | 单写瓶颈，且要支持多 worker |
| Qdrant 本地 → 独立服务 | 本地模式不能多进程/多机 |
| HTTPS + 反向代理 + 只读副本 | 现在只绑 127.0.0.1，别的机器连不上 |
| 备份与恢复脚本 | 业务库、向量、原件三处要一致 |

验收：`ab -n 1000 -c 50` 下 QPS ≥ 100、p95 < 1 s；断网演练可恢复。

## 原则

- 每一期都先补测量脚本，再改代码，改完用同一脚本对比
- 任何一期不通过验收就不进入下一期
- 期间保持「单机演示版」可用，不破坏现有 422 项测试与 18 项业务流
