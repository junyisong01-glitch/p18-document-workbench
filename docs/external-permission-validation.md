# 文档外发权限：本机人工确认机制

基线为 main `28e5e5a504e601f9d8dbcb33af055d1830965d93`，独立分支 `codex/p18-external-permissions`。正式8765及既有隔离环境未修改，本轮不做正式部署。

## 实现及人工操作

文档管理详情新增“外发权限”，保持三模块原布局。审核弹窗参考用户效果图，去除公开来源输入、审核人、口令字段；有两个类别、三项必须全选的检查、取消/确认和成功弹窗。公开资料类别 `public_verified` 只表示本机操作者声明已人工核对，不是系统已验证公开来源或管理员身份。完全虚构类别为 `fictional`。没有自动或批量授权。

先完成文档解析及必要入库复核，再打开“审核外发资格”，逐份核对内容/使用条件，选择类别并全部确认。后台绑定真实文档ID、当前解析版本和原有内容指纹。授权不能代替入库复核。授权后去知识问答重新检索，只有后台判定获准的有效片段可选；每轮仍查看实际问题、必要历史、证据、模型与实际HTTP接收地址，再人工确认。取消不改变许可；撤销立即影响后续核验。重新授权也不能复用旧待发送票据。

## 接口和存储

- `POST /api/documents/{id}/external-permission`：严格字段 revision、fingerprint、classification、checks。类别只接受fictional/public_verified；三项检查必须是布尔true且不能缺项或多项。不接受前端正文、审核人或授权状态。
- `POST /api/documents/{id}/external-permission/revoke`：revision和fingerprint核验后撤销。通过同样本机/同源安全中间件。
- 原文档列表/详情增加 external_permission 后端状态；指纹/版本变化后许可不再有效，替换新文档ID不继承。
- 首次授权/审计写入时，仅在当前数据目录SQLite中创建 `external_permissions` 和 `external_audit` 两张新表。不改原documents/events/chunks/index_runs，不重建索引。
- 许可记录与授权/撤销审计在同一SQLite事务提交。新记录（包括撤销）优先于旧 `rag-permissions.json`；旧脚本许可兼容保留，不自动升级为public_verified。新许可记录为 `local_human_confirmation`，身份一律 `local_unauthenticated`。
- 外发审计记录准备、放行/阻止、发送尝试、返回或安全错误码；保存时间、请求ID、文档/片段ID、版本、类别、确认项、内容指纹、问题哈希、必要历史轮数、消息哈希（选择协议）、接收端点、模型及模拟/真实客户端标签。不保存密钥、问题/原文全文、模型敏感响应或伪造审核人。发送结果使用实际放行时的来源元数据快照。授权失败也有安全错误码记录。
- 前端不接收/覆盖外发目标。许可摘要绑定确认票据，撤销后重新授权仍导致旧票据失效；发送前后继续校验当前来源和许可。审计写入失败时，在发送前失败则阻止客户端调用。

## 已知边界及回退

此机制仅本机单人演示，无身份认证，不提供企业权限、防篡改审计或法规符合性保证。操作者必须确认公开/许可条款允许向第三方模型发送。方案B严格撤销仍未实施：发送前最后核验与真实网络发送之间存在窄竞态；已发送内容不能撤回，发送后失效则不发布回答。界面授权/撤销不承诺撤回已发送数据。现有Word定位、检索排序、临时会话等限制保持。

尚未增加审计浏览/导出界面、企业账号、真实公开来源自动核实或长期会话。数据库审计可由本机维护者只读查询，运行数据不上传GitHub。回退代码时保留新表；旧代码不识别新许可且可能重新读取旧JSON记录，回退前必须停止外发生成并核对旧许可，不得通过删除新表“回滚权限”。正式升级及备份另行授权。
