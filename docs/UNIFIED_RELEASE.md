# P18 统一版整合与验收记录（2026-11-15）

## 唯一版本的含义

GitHub `junyisong01-glitch/p18-document-workbench` 的 main 是唯一维护基线；本机 Demo V1 目录是这份代码的运行副本，统一入口为 `http://127.0.0.1:8896/`。文件、检索、问答、身份页面使用同一个 React 应用，`/library/` 兼容地址也返回它。历史分支、交付 ZIP、旧网页文件和旧工作区保留作追溯与回退，不继续当作当前版维护。

“代码统一”不等于合并数据库。原6份演示资料与30份启辰资料仍独立：前者使用原生可写库，后者使用只读加载器及服务端四岗位 ACL。不得把历史库或模型、凭据提交 Git。8765/8876/8892 与封存实验保持原样，不将8896的切换称为8765发布。

## 合并内容及未采用内容

- 基线：已归集的 Demo V1 审查代码 `cdcb02acb6e75bbb818c1d06036f22f1f55b381e`。
- 接收交付包的新版 React 页面、样式和组件，使用锁文件独立构建；不覆盖接收包所省略的后端模块。
- 清除固定演示账号、伪造检索和占位下载；列表、统计、库切换、上传、复核、检索、下载都走已有真实接口。
- 复核显示服务端实际解析 blocks 和必选检查，不在浏览器伪造复核完成。
- RAG 保持原生 drafts → 人工选择 → selection → 完整 messages 预览 → 明确确认发送；仍是最多8组、20000字符。缺少配置不能发送；启辰30份库保持本地只读、不可外发。
- 来源查看传递 revision、index_token、chunk_id，由原生 source_guard 校验；展示命中片段及真实来源坐标。Word/PDF保留转换预览，Excel精确单元格跳转仍未实现。
- FastAPI仅改统一页面入口和详细文档返回复核要求。E2切分、Embedding、BM25、RRF、去重、权限、外发协议和提示词不变。
- 未采用交付包的Docling/AnythingLLM接入、批量初始化和账号种子、安全锁重写、数据库改造；未引入新Python依赖。交付包声称的功能不自动成为本版能力。

## 运行、更新与回退

新检出按README准备独立Python环境和前端构建；`prepare_review.py`只供空目录初始化，不得在现有运行库执行。模型、转换器、私有ACL、原件与运行数据须本机另行配置，不能由Git恢复。

本机更新先保存原运行源码/构建与哈希，核对数据及服务PID，停止本次拥有的8896服务后仅替换经测试的程序文件；保留本机config、runtime、缓存与凭据。用原启动入口以本地模式启动，复核文档数、源文件、索引身份与网页链路后保持运行。需要AI时用户自行隐藏输入临时密钥，不从旧进程提取密钥。

失败回退先停止新版8896，恢复本地回退清单内的程序和构建文件，移除仅本轮新增的程序文件，再用原启动入口启动。业务库不混合、不重建；若数据校验异常立即停止，不能用代码回退声称数据库已恢复。Git保留原提交与分支，普通推送、PR合并，不强推、不抹除历史。
