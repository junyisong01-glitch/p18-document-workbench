# 替换保护与失效向量清理（2026-11-16）

用户要求继续验证未启用项。此次只适配新包的生命周期机制，不照搬其按文档全量删除的清理逻辑，不改模型、检索排序和既有数据。

## 已接入的最小行为

1. 语义索引启用时，新文件解析/复核成功不再立即停用旧文件。必须是ready状态、当前有效的complete索引、真实向量点完整，才允许替换；索引初始化失败、切分失败、向量失败或快照失效时保留旧文件。同一旧文件已有ready但未完成索引的替换时，不允许再并行挂另一份替换。
2. 索引完成回调和重启后的已有完整索引都可以补做替换，不重新编码。替换记录/审计失败不把已发布的新索引改判失败；记录replacement_pending，恢复时重试，审计补记幂等。此标记在后台索引JSON中保留，本轮未新增前端提示。
3. 向量清理最多尝试两次；只删除指定document_id和旧token匹配的点，且核对当前代次仍是失效状态。代次已变、新索引有效或缺少token则保守跳过。失败后stale记录保留，启动恢复时再尝试，不新建数据库字段。
4. 清理不在持有业务锁时等待向量锁；取得向量锁后，对业务锁只非阻塞尝试，忙则保留记录待恢复。替换的向量存在性检查遇锁忙也延后，避免检索与清理互等。该策略优先保障检索与资料可用，不能保证每个旧向量立即回收。

语义关闭的旧本机测试模式保留原流程；8896启用了语义后端，执行上述保护。启辰只读Index覆盖禁止recover/invalidate/delete，不允许通过本功能写入30份库。

- 索引状态只记complete但实际向量缺失，不允许停用旧文件；锁忙则保持旧文件，记录延后。已完成索引不因替换簿记故障退回failed。
