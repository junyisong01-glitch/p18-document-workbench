## 3. 建议的最小新增协议（名称/字段待确认）

保留旧prepare和answer兼容，新增两个仅本机接口；复用RagService内存会话及现有检索，不新增业务数据库或长期会话表。

### 3.1 POST /api/rag/drafts：本地候选草稿

输入question、可选session_id；不接受客户端历史、正文或“已授权”标志。

后端生成不可猜测的draft_id，绑定当前会话版本、问题、实际必要历史、配置摘要、每个候选的来源/版本/索引及成员。返回candidate_id、文件名、章节、摘要与展开正文、风险、members、本地显示资格、可外发选择资格及原因、默认勾选建议和预算信息。

检索继续使用同一个SemanticService、Qwen、Qdrant和当前配置的vector/hybrid/hybrid_dedup。为保留PR #7修复的“未授权候选不能挤占获准候选名额”保证：

1. 获准通道：沿用`document_filter=allowed`，过滤在向量/BM25截断前生效，召回Top-20。
2. 本地展示通道：对有效已审核可检索片段召回Top-20，用于补充未授权的本地候选。
3. 服务端合并身份，分别标明获准召回与本地候选顺序，不把双通道排名误写成单次全库排名。最多来自两个20条列表，去重后实际数量返回，不写死“5条”。两个通道使用原算法及参数，不改变知识检索默认配置。首版允许两次查询编码的额外成本，先测量；不为优化这点重构检索引擎。

不能先全库Top-20再过滤许可，也不能从旧prepare裁剪后的8组倒推全部候选。候选只涵盖真实召回范围，不承诺全库所有答案可见。

`hybrid_dedup`必须保留全部真实来源身份。混合许可组先按成员许可拆成“可选择的获准成员组”和“仅本地成员组”，保持关联，不把未授权成员悄悄带入获准组的members，也不声称未发送成员被模型引用。

默认勾选仍只来自获准、有效、可放入预算的组；其余保留在本地列表并注明未默认勾选原因。没有获准证据时仍可本地查看；不能生成发送票据，不能自动改授许可。

### 3.2 POST /api/rag/selection：选择更新与发送预览

输入draft_id、服务端选择版本和candidate_ids；只认服务端草稿中的身份，不接受客户端正文/来源/许可。每次选择更新使旧发送预览失效，前端改选即时丢弃旧票据并同步；同步期间不能确认发送。请求串行或使用版本冲突处理，晚到响应不得覆盖新选择。

后端重新核验当前会话、所有所选成员的解析/片段/索引/许可、历史来源和模型配置；计算**完整实际发送消息**的字符预算，包含系统提示、问题、实际历史、证据JSON和编号，不只算正文。

- 空选择、仅本地ID、未知/跨草稿ID：明确拒绝，不产生可发送票据。
- 超默认组数或字符预算：返回组数/用量/上限及原因；保留用户选择，禁止发送，不自动删减，也不截断表格/代码。
- 检索默认建议未勾选的组：告知原因；用户可换选以让第9组等正确证据进入预算。
- 有效且未超限：只对实际选择生成S1…Sn，并生成一次性发送票据。返回准确问题、实际必要历史、目标服务/模型、所有证据完整正文与来源成员、预算用量、选择版本及有效期。模型上下文只能从此服务器快照构造。

选择同步失败/配置或来源变化时，关闭或禁用旧确认弹窗，要求重新选择/检索。服务器只能对已收到的更新作保证；不能假称知道尚未送达的浏览器动作。真正提交answer前仍做现有全部检查。

### 3.3 POST /api/rag/answer：沿用发送接口

继续ticket+consent:true，不直接接收片段正文。内部额外绑定draft/selection版本；旧选择票据、重放、并发使用均拒绝。只在用户核对弹窗中的问题、历史、全文和目的地后调用；不因“选中”就发送。网络失败或超时不自动重试，重试重新准备并确认，提示可能已计费。

继续复用三态结构化响应、引用编号校验及发送前后valid检查。历史只记录实际发送的获准证据，未授权本地候选不得进入消息、问答历史、引用成员或外部错误日志。增加明确的本地错误码，例如draft_expired、selection_changed、selection_forbidden、selection_empty、evidence_budget_exceeded；不记录密钥或完整敏感响应。

此处“选择版本”只解决本轮用户同意内容的一致性；**不实施暂缓的严格许可撤销方案B**。许可最后校验到网络发送的既有竞态窗口仍存在，限人工授权的完全虚构资料教学使用，不能宣称企业级撤销保证。

## 4. 新前端与安全策略兼容

当前预览会替换body、移除旧样式、载入大量内联样式及Google字体；只能作为隔离视觉预览。现有正式后端CSP为script-src/style-src 'self'，不能直接照搬预览运行器，更不能放宽CSP以迁就设计。

建议保留13份模板、preview.js和8771作为视觉基准；新增生产容器与控制器，把设计内联值映射到独立同源`qa.css`和组件类、把tokens映射到QA范围。生产代码不清空body、不删除旧模块样式；只挂载新版问答容器，保留文档/检索DOM与原控制器。QA内“文档/检索”通过既有导航桥返回旧页面。数据来自API并转义，不把文档文字作为HTML执行。

字体沿用既定栈和本机回退。若需所有机器统一Noto字体，另行核对可分发字体及许可证并本地托管，不通过开放外链字体域来规避CSP；未取得字体资产前不承诺像素级一致。

真实模式不得导入虚构状态数据或失败后回退模拟。隔离模拟客户端须用明确execution_mode/测试配置标记，健康状态区分真实客户端与离线模拟；“API已配置”不等于认证成功。左栏真实模式只显示当前内存会话/刷新清空提示，固定演示历史仅保留在预览入口。13号开发文案页不进入普通导航。

真实列表总数、默认选中数、默认不选原因均由API返回，修正05参考“5条但只绘4行”的演示差异。保留已验收字号、布局、图标8px间距及证据层级，不新增视觉设计。

## 5. 许可复核与真实原文联动

- 文档审核通过不等于有外发许可；默认无许可，按当前revision/fingerprint检查。仅本地行不能勾选，UI不提供“勾选即授权”。人工授权继续通过已有CLI，指定文档ID、解析版本、确认人和fictional分类；本阶段不扩大到真实脱敏企业资料。
- 预览/来源显示权限与外发许可是两回事：有效本地来源可核对，未授权内容不得进入发送快照。去重组切换来源时显示实际成员文件和可靠位置，而非统一使用代表文件页码。
- 引用编号仅映射answer返回的真实citations/evidence，绝不解析模型自造的文件名/页码作为来源；证据不足没有回答引用，“查看检索依据”仅显示候选/提供证据，不冒充答案依据。
- 直接复用文档详情、index状态、preview meta/page/file及sourcePage。PDF使用实际物理页，Word只使用已有可靠preview_pages；没有映射时显示结构位置并允许“从首页浏览（非定位）”，不猜页码。
- **必要的小型兼容改动**：现有预览/下载GET未校验query中的revision。建议对QA请求携带的revision及可选成对的chunk_id/index_token增加服务端读取时检查，旧页面不带这些参数时保持原行为；有来源身份参数时，验证当前片段仍有效，失效返回明确409，不让旧引用加载为新版本预览。返回原文前与前端切换响应均做校验，防止慢响应覆盖新选择。此为RAG来源衔接，不改Word解析或模块二算法。
- 版本守卫保证请求读取时版本匹配，不宣称浏览器多次请求/后续人工操作具有全局原子性。关闭右栏、翻页、下载、切换成员、预览失败仍保留可用可靠来源信息。
