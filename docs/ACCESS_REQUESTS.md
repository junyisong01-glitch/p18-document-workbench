# 资料支持申请与借阅审批

适用版本：2026-11-24 AR1。正式教学工作台使用已有业务资料库与账号权限。

## 用户路径

1. 内部员工在知识问答的回答下点击「申请资料支持」。系统带入当前问题，员工选择相关部门并填写用途。
2. 申请送达所选资料部门主管的「文档管理 → 借阅申请」，管理层也可处理。主管处理的是借阅申请，不是文件发布审核。
3. 主管点击「处理申请」，先点击「相关资料推荐」中的文件名展开原文片段，再点击「选择此文件」；也可从下方列表手动选择本部门一份已发布、可检索且有权授权的文件，选择 1、3、7 或 30 天，点击「批准并授权」。也可以不批准；申请人可在待处理时撤回。
4. 员工通过问答页顶部「我的申请」或「文档管理 → 我的申请」查看结果。站内每 5 秒更新，也可以主动刷新。
5. 批准后点击「重新提问」。系统刷新权限，并新建问答检索上下文，避免复用批准前的无依据结果。旧回答不会被静默改写。
6. 主管可在现有「借阅记录」中撤销授权。到期、撤销、下架或归档后重新检查当前访问资格；无其他有效权限时，不再提供文件信息或用于新的问答。

## 演示路径

提前分别在两个独立浏览器会话登录，避免同一浏览器的多个标签共享登录状态。员工为何见山（生产制造部），主管为林岚（研发部）。

问题：**设备持续离线达到多少分钟仍未恢复时，应提交 IT 工单？**

- 何见山先问：当前演示数据下显示「没找到可靠依据」，没有目标文件引用。
- 点击「申请资料支持」→ 相关部门选择「研发部」→ 用途填写「生产现场设备离线，确认转工单时机」→ 提交申请。
- 切换林岚 → 文档管理 → 借阅申请 → 处理申请 → 选择 **QC-RD-SUP-021 设备离线排查操作手册.docx** → 期限 1 天 → 批准并授权。
- 切回何见山 → 我的申请 → 重新提问：实际本地模型回答的关键结论为 **10 分钟**，引用获准的操作手册。点击引用核对原文；不要求模型逐字复现同一句话。
- 切回林岚直接问同一问题：其已有研发部阅读权限，可以直接得到 10 分钟的答案，引用范围可能包含其他研发资料。
- 演练结束可由林岚在借阅记录中撤销何见山对该文件的授权，恢复下次演练前的权限状态。已合法展示的旧答案或用户保存的内容不能通过撤销收回；演示撤销效果应使用新一轮提问并尝试再次打开来源。

推荐讲解：「同一个问题，系统按账号权限检索。缺少依据时，员工可以说明业务需求，由资料所属部门主管决定共享哪份文件。批准后，同一问题就能获得有原文依据的回答。」

## 权限与隐私边界

- 「没有可靠依据」可能是资料不足或检索不命中，不能据此断言存在某个无权查看的文件。申请入口不检索、不列出隐藏文档名称、摘要或 ID；由主管根据需求选文件。
- 普通员工只能看到自己的申请。主管只能处理目标部门与自身部门一致的申请；管理层可跨部门处理。任何人都不能批准自己的申请。
- 普通主管不能借此授权机密文件；机密文件仍由管理层处理。批准仅添加现有只读借阅权限，不授予编辑、发布或再授权权。
- 服务端处理时重新检查申请人有效性及部门、审批人身份、文件部门与状态、索引有效性以及申请和文件版本。申请结果、授权和审计在同一事务写入，重复或过期审批返回冲突。
- 已有永久或更长的借阅授权不会被本次短期批准缩短。申请每次读取重新检查文件当前可读性，不把已撤销文件名称保存在面向申请人的响应中。
- 当前是单文件、单级批准，采用站内状态更新。未增加邮件/即时通信通知、自动发现隐藏资料、自动推荐授权或多级会签。

## 数据与部署

首次加载业务库时自动创建 `access_requests` 和 `access_request_events` 表及待处理申请去重索引，无须手动改库。原有表和授权规则保留。

更新源码并重新构建前端后，重启服务即可启用。部署交接导出工具已将两个新表纳入清理规则：不导出问题、用途和申请审计；已有借阅授权仍遵循原有演示资料包策略。此前已制作的资料包不需要为这两个空表重新导出。

## AR2 主管选件辅助（2026-11-24）

实际使用中，问题申请已批准但仍没有答案，核对发现授权的是《设备监控平台接口说明 V1.3》，并非包含转工单时机的《设备离线排查操作手册》。这属于所选资料与问题不匹配，不能把「已批准可查阅」解释为「问题一定有答案」。用户原有批准记录保留，不自动撤销或替换。

主管审批弹窗新增相关资料推荐：按申请中的问题检索主管本人可阅读且可授权的目标部门已发布资料，展示至多5份候选及命中片段。主管自行核对内容和用途、点击选择后批准；不会自动选定第一项。可继续手动选件。推荐只表示相关性，不保证包含完整答案。

推荐接口仅供有权处理该申请的主管/管理层使用，禁止申请人和无关部门读取。检索前过滤部门、权限、机密授权资格和有效索引，返回前再次检查申请状态及文件权限；不使用超级账号检索，不向员工透露隐藏资料。无候选说明仅限当前主管可授权范围，不能断言整个知识库没有相关资料。

员工如需看到具体「可借阅文件」目录，应另建由资料负责人明确允许公开的目录范围。当前文件阅读权限不等于目录公开权限，本轮不自动开放文档存在性或文件名称。知识缺口反馈沿用已有「反馈」入口。


## AR5 推荐依据与选择（2026-11-24）

主管打开申请后，系统在其可授权资料内检索，并通过本机Ollama核对命中片段。默认展示两份候选，将有可核对原文支持的资料排前并标“优先核对”，其他资料收在“更多相关资料”。卡片展示原文依据，点击标题仍可展开完整命中片段；主标题隐藏编号，展开后显示编号。

对于“设备持续离线多久提交IT工单”，服务台报障与升级指南、离线排查手册都有10分钟的明确处理条件。只需确认报障时机可先核对指南；需要现场排查步骤可选择操作手册。无需给同一员工批准所有相似资料。仍由主管结合用途选定一份文件与期限，系统不自动选中或批准。

推荐辅助核对不保证全部问题都能准确识别。引用必须逐字匹配当前候选原文；本机模型不可用、超时或结果不完整时显示普通候选并保留手动选件。核对期间申请或文件权限/版本变化会重新检查。部署需沿用配置的本机Ollama模型，不会外发，也不会自动下载模型。

当前优先提示主要用于单一明确问题。检测到多个疑问焦点或明确多项要求时，保留为普通候选，由主管核对每项需求，避免把部分答案当完整依据。

AR6界面更新：默认从推荐卡片选择文件，下方显示本次借阅文件；需改选其他资料时展开“手动选择其他文件”。推荐为空或加载失败时手动入口自动展开。审批按钮为“不予批准”和“批准并授权”，权限语义不变。

AR7界面更新：下方“借阅设置”统一展示选件状态、醒目的“手动选择文件”按钮和借阅期限；手机按钮占整行。手动入口和审批行为保持不变。

AR8界面更新：审批顶部按申请人、申请问题和使用用途整理为摘要区域，保留全文，长用途自动换行；授权行为不变。

AR10界面更新：手动选件标明申请所属部门，按文档类型分组并显示数量，未分类置后；仍仅列出本次申请所属部门中当前主管可授权的已发布且可检索文件。

AR11界面更新：点击“手动选择文件”打开独立弹窗，按类型筛选或按名称/编号搜索，选择后点击“确认选择”返回审批。取消不改变原选择；推荐为空或失败时保留手动入口，不自动弹出。选件范围及授权规则不变。

## AR18 处理信息（2026-11-24）

待处理申请以相关部门主管或管理层为审批范围，不表示已分派给个人。接口reviewer_scope仅待处理时返回；handled_by为已处理申请真实记录的actor，旧记录缺失时为空。界面显示实际批准人、处理人或撤回人；角色变化或文件阅读权撤回不会改写历史处理人。现有权限校验、本人不得自批及隐藏不可读文件信息的规则不变。

## AR21 资料缺口与补充跟进（2026-11-24）

未结束状态为pending（待核查）和needs_content（待补充）。同一申请人、相关部门和标准化问题在两种状态下统一去重。主管或管理层核查后可选择approve、needs_content或reject；申请人可cancel。needs_content可再次更新说明、reject、cancel或resolve，禁止用普通approve绕过补充完成说明。resolve仅对needs_content有效，必须关联所属部门已发布、可授权、可阅读且有有效索引的资料，并提交最新文件版本。

needs_content、reject、resolve的note去除空白后必填。note会向申请人展示，不得放入未授权文档名称或片段。review_note保存最近结果；gap_note/gap_actor保存最近缺口说明和核查人；逐次说明追加在access_request_events.note中。负责部门沿用申请department，不虚构个人指派。resolve原子创建只读借阅授权并将申请变为resolved；授权不会缩短已有更长或永久授权。

员工分类：pending/needs_content进入待处理，approved/resolved且实时access_available为真进入可查阅，其余进入历史。发布文件不会自动结束申请；主管核对关联文件并完成补充后，轮询更新结果，员工可重新提问。文档权限撤回或状态变化后，返回结果继续隐藏不可读文件ID和名称。

兼容迁移仅增加可空字段与未结束申请唯一索引，重复启动安全。暂未加入自动全库探测或公开受限目录，不根据检索失败宣称整个知识库不存在答案。


## AR23 多文件审批（2026-11-24）

当前替代上述单文件选择规则：推荐和手动选件均支持多选，不自动选中或批准。应按实际用途选择必要资料，两个片段包含同一答案不代表两份都必须批准。已选汇总可移除；手动弹窗取消保留原选择，确认返回全部选择。

approve和resolve接受documents: [{id, version}]，1至50项，不允许重复ID。旧document_id/document_version继续兼容，但不可与documents混用。全部文件必须通过同部门、审批资格、发布状态、阅读权限、有效索引和版本校验后，单事务更新授权、文件版本、关联与事件。任意失败不产生部分授权；既有更长或永久权限逐份保留。

access_request_documents记录申请到多文件的关联及各自有效期，启动时幂等回填旧approved/resolved申请，不修改旧授权。返回documents只包含调用者当前可读文件，每份含id、name、expires_at；旧document兼容返回首份可读资料。access_available代表至少一份当前可读，部分撤权时其他文件继续可用。员工页逐份展示当前可查阅资料，未授权或已失效文件信息不返回。
