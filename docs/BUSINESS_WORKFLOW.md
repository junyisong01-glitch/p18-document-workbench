# 独立业务库与四种职责

本地演示改动，未部署公网。启辰业务库是核验后另建的可写副本，历史验收库和六份演示库不合并。`config/business.json` 是本机配置，不进 Git；例子见 `config/business.example.json`。启用前必须由可信维护者核验独立数据目录、原件哈希、原岗位 ACL、模型配置和账号，放置私有 `business-seed.json`。缺少配置或种子时不会自动接入旧库。

## 操作与权限

|职责|提交|审批与发布|阅读|删除与公开|
|---|---|---|---|---|
|老板|可选择五部门|可处理他人提交；不能自批本人资料|业务库全部；检索仍排除历史、待审、回收站|唯一物理删除者；任免主管；批准公司公开|
|部门主管|本部门|本部门他人提交，解析复核后批准、索引就绪后发布|部门资料及获准共享；旧文档岗位限制保留|本部门软删除、恢复、普通文档借阅；不物理删除|
|员工|本部门，上传新版本|无|已发布部门资料、公开及单独授权；旧岗位例外保留|无删除和公开权限|
|只读访客|无|无|已发布公开及单独授权；不能凭所属部门获得读权|无|

机密资料默认不按部门全部开放，原 EXT 岗位例外继续执行；主管不自动获得这些例外。受限资料共享须老板明确授权；EXT-13 运维冲突不自动放行。全公司公开是独立读权，不改写原件密级，也不授予外部 AI 许可。借阅授权只适用于所选版本，新版本不自动继承借阅授权；原有岗位读权限制和机密级别下限自动保留，不能通过上传新版本暗中放宽。

流程：员工提交 → 本部门主管（非上传者）查看原件、完成必要解析复核 → 审核通过并生成索引 → 索引就绪后发布。发布前其他员工看不到待审资料。退回需原因，上传者可重提或上传修订文件，旧提交留存。主管本人提交由老板审；老板本人提交由对应部门主管审。

上传新版本不覆盖原件；新版本发布时在一个 SQLite 事务中将前版归档。历史原件在读权内仍可查看，但不进入搜索/问答候选，老板也一样。回收站仅老板/对应主管可读；恢复不擅自取消历史归档。物理删除须先软删除，再由老板输入当前文件 ID 确认，仅清理所选版本，不连带删除其他历史版本；保留最小审计和删除墓碑，既有备份不会被自动销毁。

## 启动与页面

现有安装仍用 `scripts/experience.py --local`；账号正常密码登录继续有效。本机演示快捷入口只有中央数据目录明确存在 `business-demo-enabled.json` 且值为 `{"enabled":true}` 时开启，并同时核查 Host 和客户端均为回环地址。仅已配置职责的活跃演示账号可选，老板仍须密码。跨主机访问不开放此快捷入口，生产环境不得启用。

登录后选择“启辰业务知识库”，文档管理可见“已发布 / 我的提交 / 历史归档 / 提交资料”；主管增加“待审核 / 待发布 / 回收站”，老板增加“人员职责”。无权动作在服务端同样拒绝，隐藏按钮不作为授权依据。任免主管会使目标账号旧会话失效，需要重新登录。

业务库始终禁止外部模型发送，不因配置个人 Key、全公司公开或老板身份放行。六份演示库仍沿用原逐份外发许可和原生 RAG 协议，配置 Key 不代表资料获准外发。发送前最后检查与实际联网之间的撤权竞态仍是企业机密上线阻断项。

## 实现与验收边界

- `app/business_roles.py`：职责、部门、岗位、唯一老板、会话失效和本机演示入口。
- `app/business.py`：业务状态、文档级读权、版本、审批、借阅与审计；复用原解析器、E2 切分、向量模型、索引和源坐标。
- `app/datasets.py`：中央认证，路由到独立业务副本/原演示库/历史只读库；选择库不能增加读权。
- `frontend/src/pages/BusinessPage.tsx`：真实提交审核界面，无浏览器伪造审批。
- `tests/test_business_workflow.py`：隔离 SQLite/HTTP 权限及状态回归；测试中的技术索引是替身，真实模型和 Chrome 证据另保存在本机验收目录。

保留原有前端检索、来源预览和个人模型配置成果；不改 E2 排序、Embedding、系统提示词，不自动授予外发许可。权限表描述业务库，不能等同于历史库或演示库的旧权限。该版本仍是可信本机演示，不代表企业生产安全验收。
